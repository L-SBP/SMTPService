# Android邮箱项目后端接口和模型设计文档

## 一、项目概述

本文档基于Android邮箱客户端项目，为后端Spring Boot项目提供完整的接口设计和数据模型定义。文档详细描述了所有需要实现的REST API接口、请求/响应模型以及相关的业务逻辑。

## 二、技术栈

### 后端技术栈
- **框架**: Spring Boot 3.x
- **认证**: Spring Security + JWT
- **数据访问**: Spring Data JPA
- **数据库**: MySQL/PostgreSQL
- **缓存**: Redis (可选)
- **构建工具**: Maven/Gradle
- **API文档**: Swagger/OpenAPI

## 三、通用模型定义

### 3.1 通用响应模型

```kotlin
data class ApiResponse<T>(
    val success: Boolean,      // 操作是否成功
    val data: T?,              // 响应数据
    val message: String?,      // 消息描述
    val errors: List<String>?  // 错误列表
)
```

### 3.2 分页响应模型

```kotlin
data class Page<T>(
    val content: List<T>,      // 当前页数据
    val totalElements: Long,   // 总元素数
    val totalPages: Int,       // 总页数
    val size: Int,             // 每页大小
    val number: Int,           // 当前页码(从0开始)
    val first: Boolean,        // 是否是第一页
    val last: Boolean          // 是否是最后一页
)
```

### 3.3 群组分页响应模型


## 四、用户认证接口 (AuthController)

### 4.1 用户登录

**接口路径**: `POST /api/auth/login`

**请求头**:
```
Content-Type: application/json
```

**请求体**:
```json
{
    "username": "string",     // 用户名
    "password": "string"      // 密码
}
```

**响应**:
```json
{
    "success": true,
    "data": {
        "token": "eyJhbGciOiJIUzI1NiJ9...",  // JWT Token
        "user": {
            "id": 1,
            "username": "john_doe",
            "email": "john@example.com",
            "signature": "Best regards, John",
            "isAdmin": false,
            "quotaLimit": 100.0,
            "usedSpace": 15.5,
            "lastLogin": 1640995200000
        }
    },
    "message": "登录成功",
    "errors": null
}
```

**错误响应**:
```json
{
    "success": false,
    "data": null,
    "message": "用户名或密码错误",
    "errors": ["用户名或密码错误"]
}
```

### 6.6 标记邮件为已读/未读

**重要说明**: 
**草稿功能完全在Android客户端本地实现，通过SQLite数据库存储和管理，不与后端进行数据同步。**

**原因**: 
1. 减少网络传输和服务器存储压力
2. 提高草稿保存和加载速度
3. 保护用户隐私，草稿内容不会上传到服务器
4. 支持离线编辑草稿

**实现方式**:
- 草稿管理完全在本地进行
- 客户端直接从本地数据库读取草稿列表
- 不需要与后端进行草稿数据同步

**接口路径**: `PUT /api/emails/{id}/read`

**请求头**:
```
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
Content-Type: application/json
```

**路径参数**:
- `id`: 邮件ID

**请求体**:
```json
true  // 或 false
```

**响应**:
```json
{
    "success": true,
    "data": "标记已读成功",
    "message": "标记已读成功",
    "errors": null
}
```

## 九、数据库设计建议

### 9.1 用户表 (users)

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    signature TEXT,
    is_admin BOOLEAN DEFAULT FALSE,
    quota_limit FLOAT DEFAULT 100.0,
    used_space FLOAT DEFAULT 0.0,
    last_login TIMESTAMP NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_username (username),
    INDEX idx_email (email)
);
```

### 9.2 邮件表 (emails)

```sql
CREATE TABLE emails (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    sender VARCHAR(255) NOT NULL,
    recipients TEXT NOT NULL,
    cc TEXT,
    bcc TEXT,
    subject VARCHAR(500),
    body LONGTEXT,
    has_attachment BOOLEAN DEFAULT FALSE,
    is_read BOOLEAN DEFAULT FALSE,
    is_starred BOOLEAN DEFAULT FALSE,
    size INT DEFAULT 0,
    received_time TIMESTAMP NOT NULL,
    folder_type ENUM('INBOX', 'SENT', 'DRAFT', 'TRASH') DEFAULT 'INBOX',
    user_id BIGINT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    INDEX idx_user_folder (user_id, folder_type),
    INDEX idx_user_received (user_id, received_time),
    INDEX idx_sender (sender),
    INDEX idx_is_read (is_read),
    INDEX idx_is_starred (is_starred)
);
```

### 9.3 附件表 (attachments)

```sql
CREATE TABLE attachments (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    email_id BIGINT NOT NULL,
    file_name VARCHAR(255) NOT NULL,
    file_size BIGINT NOT NULL,
    content_type VARCHAR(100),
    file_path VARCHAR(500),
    uploaded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (email_id) REFERENCES emails(id) ON DELETE CASCADE,
    INDEX idx_email_id (email_id)
);
```

### 9.4 群组表 (groups)

```sql
CREATE TABLE groups (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    description TEXT,
    member_count INT DEFAULT 0,
    created_by BIGINT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (created_by) REFERENCES users(id),
    INDEX idx_created_by (created_by),
    INDEX idx_name (name)
);
```

### 9.5 群组成员表 (group_members)

```sql
CREATE TABLE group_members (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    group_id BIGINT NOT NULL,
    account_id BIGINT NOT NULL,
    joined_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (group_id, account_id),
    FOREIGN KEY (group_id) REFERENCES groups(id) ON DELETE CASCADE,
    FOREIGN KEY (account_id) REFERENCES users(id) ON DELETE CASCADE,
    INDEX idx_account_id (account_id)
);
```

## 十一、异常处理

### 11.1 统一异常处理器

```java
@ControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(AuthenticationException.class)
    @ResponseBody
    public ApiResponse<?> handleAuthenticationException(AuthenticationException e) {
        return ApiResponse.error("认证失败: " + e.getMessage());
    }
    
    @ExceptionHandler(AuthorizationException.class)
    @ResponseBody
    public ApiResponse<?> handleAuthorizationException(AuthorizationException e) {
        return ApiResponse.error("权限不足: " + e.getMessage());
    }
    
    @ExceptionHandler(ValidationException.class)
    @ResponseBody
    public ApiResponse<?> handleValidationException(ValidationException e) {
        return ApiResponse.error("参数验证失败: " + e.getMessage(), e.getErrors());
    }
    
    @ExceptionHandler(Exception.class)
    @ResponseBody
    public ApiResponse<?> handleGeneralException(Exception e) {
        log.error("系统异常", e);
        return ApiResponse.error("系统内部错误");
    }
}
```
